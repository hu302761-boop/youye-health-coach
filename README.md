# 项目代号｜私人健康教练（Apple 原生优先 MVP）

这是私人健康教练的 Apple 原生优先 MVP。当前唯一的交付主线是 **iPhone → iPad → Mac**：共享业务层、iPhone/iPad（iOS 17+）SwiftUI target 与 Mac（macOS 14+）原生桌面端已经在此仓库中。网页仅是早期原型，不是正式产品形态。

Android 手机/平板、Samsung、华为 Android/EMUI 仍是后续产品方向，但现在**冻结功能开发**：只保留独立 Kotlin/Compose 骨架和文档，不得占用 Apple 端的实现、真机验证或安装交付时间。HarmonyOS NEXT 必须另建原生工程，当前不能声称已经支持。能力边界与恢复条件见 [CROSS_PLATFORM_ARCHITECTURE.md](CROSS_PLATFORM_ARCHITECTURE.md)。

## 当前可验证内容

- 今日三件事的数据模型：早餐/午餐/晚餐完整食谱卡、训练/恢复和睡前准备。
- iPhone 首页使用一张紧凑原生日卡呈现日期、进度、早午晚概览、恢复/最低版与 20 分钟自炊标记；克数和分钟级步骤只在点入具体餐卡后展开，避免把首页做成长网页。
- 可记录的健康状态：睡眠、静息心率偏离、精力、压力、饥饿冲动、消化、经期、疼痛、病症、用药/医生限制、皮肤。
- 自动调整边界：食材等价替换、低冲击替换、提醒调整和保护性退阶可自动；目标、热量框架、加量和周训练结构需确认。
- 第 1–56 天内发生的保护性退阶会生成可审计的 `PlanChange`，便于本机持久化和解释；启动准备日与阶段评估日只保留本人状态记录，不伪造训练日变更。风险信号存在时不得从历史列表直接撤回，必须先更新当天状态。
- 周复盘和自愿周报只以已发生的正式计划日为分母；“明确跳过”必须独立呈现，已完成项照实计入、未完成项按 0 项计，绝不能伪装成忘记记录或默认完成。
- 已有 56 张完整晚餐食谱卡、7 张早餐循环卡、首日/剩菜午餐卡和 56 张训练卡；规则校验会检查克数/毫升、前置、分钟步骤、20 分钟上限、冷藏/复热与低风险替换。它们是可验证的领域数据，不代表已完成真机原生界面。
- `YouyeHealthCoachApp`：iPhone+iPad、iOS 17+、SwiftUI + HealthKit 最小只读；实际训练计时仅留在本机，不向 Apple 健康写入；含本机实时姿态提示（约每 0.25 秒、可选系统音量语音提醒、无录像/上传）和食材照片确认后重排；需要完整 Xcode、个人 Team 和真机，才可签名安装与验证。
- `YouyeHealthCoachWatchApp`：仅作为已配对 iPhone 的 watchOS 10+ companion，通过经规则检查的最小字段白名单接收当日第 1–56 天三餐名称、最低训练版、恢复标志和本地计时入口。准备日、阶段评估日或跨午夜的旧日卡会失效；Watch 不自行生成计划、不读写 Apple 健康、也不录像或分析姿态。待完整 Xcode 与配对真机验收。
- HealthKit 准确性边界：睡眠/运动时长只按重叠时间并集汇总；步数和活动能量等数量样本只取完整位于查询窗口内的记录，避免把边界外整段数值记入。步数仅在近 14 天为单一来源时显示日均；检测到多个步数或活动能量来源时保留为空并说明原因，绝不直接相加或以计划数据补齐。
- 训练本机保存：离开训练详情、切后台或返回上一页时，已发生的实际计时会先停下并保存为本机“待本人确认”草稿；不会向 Apple 健康发起写入。本人可回来核对、重新开始或丢弃；只有草稿丢弃成功落盘后才能隐藏它或重新开始计时。草稿与旧版兼容字段都不进入导出或朋友周报。
- 留存边界：完整 `HealthSnapshot` 与 HealthKit 原始样本不会写入本地 JSON、导出或朋友周报；只有本人手动填写、或已实际触发当天保护性恢复所需的最小状态会本机保留，以便重开后仍能解释恢复日。
- 照片边界：计划外餐食与食材重排照片仅存当前资料的 App 私有 owner 目录；写入前在本机压缩到最多 2048px、约 2.5MB，避免 App 成为原图缓存。食材图片可由本人主动拍摄或从相册选择，但只在当页暂存，仍须填写/核对食材与克数、预览并确认当天未完成餐次的替换后才写入私有目录。它不写回系统照片图库、不上传，也不宣称自动识别完成。新引用绑定 owner，其他内测资料不能读取、删除或在全量删除时影响它。旧无 owner 引用只在加载原资料时迁移至该资料目录：新版 JSON 成功写入后才清理旧副本，日常读取不会回退到共享旧目录；若旧文件已不存在则清掉悬空引用。照片永不出现在导出或周报中。
- 内测资料边界：当前版本是“一台设备一个本地档案”，没有登录、多人切换或跨设备同步；朋友须在各自设备独立建档。系统周报只是在本机保存的可撤回记录，未来如增加系统分享，必须再次单独确认且只可使用无资料标识的最小摘要载荷。
- 预算边界：月总预算为 ¥1,500，涵盖食材、运动、通勤、护肤和缓冲；56 天跨两个自然月，食材采购仅按 8 周合计 ¥1,600、每周 ¥200 的保守预留展示。预留不是价格、付款或已花金额，只有本人手动记账才进入对应自然月预算。
- 恢复边界：若已存在的本机资料无法读取，App 会显示只读恢复页并锁定新建/保存；不会用新档案自动覆盖、删除或上传旧资料。即使恢复中随后暂时显示“未找到”，也继续锁定；只有之后重试读取成功，才恢复正常使用。恢复期间 iPhone 会清除 Watch 上的旧日卡，不发送临时餐食或训练。
- “我的日常约束”只保存在本机私有档案，可生成作息、通勤、厨房、饮食偏好与模糊活动范围的**待确认**个性化方向；它不会静默修改当前 56 天餐卡、热量、目标、训练、系统提醒或朋友周报。
- 用户可保存自己的起床、三餐、训练、睡前与静默时间表；它决定首页“现在先做这一件”的排序，不把晚起写成漏做，也不会要求补早餐或补练。iPhone/iPad 上可另外逐项打开本机提醒，只有本人主动点“允许通知并更新提醒”才会请求通知权限；提醒不含健康、食材、位置、价格或完整计划，静默时段不自动改时，关闭项目会清理旧提醒。
- “附近优惠提醒偏好”目前也只在本机保存类别开关和阈值；未接入定位、实时价格源或系统通知。未来必须由用户当次主动提供模糊地点、授权，并在可验证来源有来源/时间/条件后才可评估；其中外卖还必须是该次明确的外卖请求，保存开关绝不构成查店、查价或提醒授权。
- 56 天结束后显示只读阶段评估，分开呈现已保存记录、明确跳过与未记录日期，并汇总已录入的睡眠、保护性信号、皮肤及手动体态趋势；不会自动续期、加量或改变热量/周结构。
- `YouyeHealthCoachMacApp`：macOS 14+ 原生桌面端，使用侧栏 + 单日详情而非拉长的手机网页；可执行日卡、食谱、训练反馈、食材确认后重排、状态、复盘、导出和删除。不伪造 iPhone/iPad 的 Apple 健康读写、前摄姿态提示或跨设备同步数据。
- 实时语音提醒偏好也属于本机私有资料：新版按资料 owner 隔离；删除或恢复旧资料的残留清理只会清除该 owner 的选择，不能重置后来新建资料的选择。旧版单一开关只会在已加载原资料时迁移一次，首次设置不会读取它。
- 若本机仍保留上次 owner 指针、但对应私有 JSON 暂时缺失，App 会进入只读恢复页，不会把它当首次安装或用新档案覆盖指针；只有真正没有 owner 指针时才进入首次设置。
- iPhone 与 Mac target 都随 App 打包最小 `PrivacyInfo.xcprivacy`：声明不跟踪、不收集数据，并仅声明 App 私有 `UserDefaults` 的本机偏好用途；没有广告、分析、上传或第三方 SDK。

运行验证：`swift run YouyeHealthCoachRuleCheck`。当前命令行环境不提供 XCTest，因此以不依赖测试框架的可执行规则校验器验证关键健康与食安规则。

关键平台与第三方依赖的采用/不采用理由见 [DEPENDENCY_REVIEW.md](DEPENDENCY_REVIEW.md)；它记录的是公开资料与工程边界核查，不能替代对应 Apple 设备的实际验收。
当前可复核工程证据、真机前置条件与明确未完成项见 [RELEASE_READINESS.md](RELEASE_READINESS.md)；它不会把静态检查误写成可安装或已获 HealthKit 授权。

## 运行与验证

```bash
swift build
swift run YouyeHealthCoachRuleCheck
zsh scripts/verify_ios_project.sh
```

完整 Xcode 安装后：

```bash
zsh scripts/preflight_macos_build.sh
zsh scripts/preflight_ios_build.sh
open YouyeHealthCoach.xcodeproj
```

先在 Xcode 选择 `YouyeHealthCoachMacApp` → `My Mac` 运行桌面版（详见 [INSTALL_ON_MAC.md](INSTALL_ON_MAC.md)）；iPhone 或 iPad 则选择 `YouyeHealthCoachApp`、个人 Team 与已连接设备。HealthKit、PhotosPicker、相机和本地姿态识别仍必须在 iPhone/iPad 真机上验证，且在实际验证前不得声称已安装或已同步。

首次安装最短步骤见 [APPLE_FIRST_RUN.md](APPLE_FIRST_RUN.md)。
